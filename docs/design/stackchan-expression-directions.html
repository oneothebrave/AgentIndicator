StackChan 表情设计三套方案

这次要选择的是机器人的性格与视觉语言。三套方向使用同样的关键状态进行比较，选定一套后，再进入实屏比例与动画调试。

适配当前 320×240 横屏。以下为按屏幕比例绘制的静态设计示意，不是实机截图；动画时长和尺寸均为拟议设计参数。

先统一设计标准

从设计角度看，当前版本同时使用了大眼白、瞳孔、眉毛、嘴巴、腮红、图标和文字，视觉焦点较多。持续浮动与频繁变化又削弱了状态之间的区别。本轮优先建立统一的形状语言和动静层次。

脸成为页面主角

日常页隐藏 Source、英文状态和操作提示。连接正常时只留底部小点；断线用断开的短线标记及静止眼形。点击查看原有文字调试页。

让变化有含义

空闲安静，工作专注，等待邀请你介入。颜色只作辅助，眼形与动作也要区分状态。完成只庆祝一次，随后放松；真实状态记录仍保留 done。

示意图底部小点代表连接提示。最终亮度、可读性与动画幅度需在机器人实屏上确认。

DIRECTION A · QUIET SIGNAL

极简光眼

把两只发光的眼睛作为唯一主角。取消瞳孔、眉毛与常驻嘴巴，让眼形、间距和停顿承担情绪。适合希望机器人融入桌面、减少视觉干扰的方向。

背景 #080E13　主体 #BAEEE9　等待暖琥珀 · 异常柔红

造型规范

以竖向胶囊眼为基准，双眼中心约为 (102,110) 与 (218,110)。常态单眼 40×58 px；外轮廓圆角柔和，保持大面积留白。执行时压成短横眼，完成时弯成笑眼。

适合你的原因

最适合作为长期放在桌边的状态伙伴。远距离轮廓清晰，减少持续动画带来的分心。

动画节奏

空闲每 5–8 秒眨眼一次，闭合约 140 ms；思考时整体侧移 6–9 px，再停住观察。执行只做 2 px 的轻微收缩，等待每 2.4 秒缓慢放大一次，完成笑眼保持约 2.5 秒。

需要接受的取舍

表情性格偏内敛，editing、running、tool 的细分识别需要极小的辅助标记或点击查看。

推荐优先试做。先确认两只眼睛的比例和节奏，再决定是否需要嘴巴。

DIRECTION B · SOFT COMPANION

柔软伙伴

使用小眼睛、短嘴形和柔和的面部比例，让机器人更像一个专心陪你工作的伙伴。情绪靠轻微的不对称和嘴角表达，避免所有状态都夸张跳动。

背景 #201D24　主体 #F6EADB　等待暖琥珀 · 异常柔红

造型规范

眼睛收小为约 26×28 px，中心约为 (98,107) 与 (222,107)，扩大眼距。嘴巴位于 (160,154)，宽 26–42 px；腮红只用于空闲和完成，眉毛仅在疑问或担忧时出现。

适合你的原因

陪伴感最强，完成和等待更容易被理解为情绪。适合喜欢机器人拥有温柔性格的用户。

动画节奏

空闲每 4–7 秒眨眼；思考先看向一侧，约 700 ms 后另一只眼睛跟随，形成轻微迟疑。执行嘴形收紧，保持稳定；等待单侧抬眉，完成只做一次 3 px 的轻抬，再停留微笑约 3 秒。

需要接受的取舍

比另外两套更依赖精细比例；嘴形过多容易显得幼态。需要实屏控制腮红亮度和嘴巴大小。

如果你希望机器人像一个桌面小伙伴，优先选这一套。

DIRECTION C · PIXEL OPERATOR

像素终端

将表情限制在明确的像素网格中，用阶梯笑眼、方形眼睛和离散动作建立自己的语言。它像一位住在小终端里的操作员，状态切换直接、有节奏。

背景 #111B18　主体 #C5ED97　等待暖琥珀 · 异常柔红

造型规范

使用 4 px 基础网格，主要眼形为 32×32 px，中心约为 (96,112) 与 (224,112)。所有轮廓对齐网格；图中斜向异常眼为概念示意，落地时改为阶梯像素。主页面保持简洁，不加入代码雨。

适合你的原因

三套中状态切换最鲜明，造型容易稳定复现；与编程工具场景相符。

动画节奏

动作以 8–12 fps 的设计节奏逐格变化，显示刷新仍可保持平稳。空闲偶尔一帧闭眼，思考每 800 ms 横移一格；执行用三格指示依次点亮，等待不闪屏，完成用两帧展开笑眼。

需要接受的取舍

情感细腻度较低；过密闪烁会像报错终端，因此只让局部小元素更新。

如果你偏爱复古电子产品与工具属性，选这一套。

设计建议

我建议先看 A。Agent Indicator 的主要任务是让你在工作时用余光察觉变化，克制的双眼造型最符合这个使用方式。如果你更在意陪伴感，B 更合适；如果你喜欢明确的电子工具风格，C 更有辨识度。以上是设计判断，尚未经过你的偏好测试或实屏对比。

你只需要决定三件事

  1. 选一个整体方向：A、B 或 C。
  2. 说明最喜欢与最不喜欢的具体部位，例如眼睛太窄、不要腮红、嘴巴太小。
  3. 选择动画性格：安静、适中或活泼。

选定后，先细化空闲、思考、执行、等待、完成、异常六个状态，并在同一亮度下做实屏验收，再扩展其余状态。保留点击调试页的操作，便于核对真实事件。

设计依据：本项目当前 StackChan 固件、事件映射与 CLI hooks 接入记录。本文仅为候选设计提案，不涉及固件烧录。
